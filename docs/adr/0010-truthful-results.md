# 0010: Truthful, measured results only

**Status:** accepted (22 November 2026)

**Context:** A code review on 2026-11-22 found that several evaluation scripts hard-coded accuracy numbers, latency figures and uptime percentages rather than measuring them from real runs. Model cards and eval reports were written by hand with numbers that do not correspond to any recorded experiment. The acceptance script passed by construction.

**Decision:** All reported numbers must come from a script in the repository that writes a machine-readable result file (see `.agents/rules/no-simulated-results.md`). `MODEL_CARD.md` and `EVAL_REPORT.md` are generated by a renderer from `reports/metrics.json`; the renderer raises an error when a placeholder has no value. If a measurement has not been taken, the value is written as `NOT MEASURED`. The acceptance script in `--strict` mode exits non-zero when any required gate is missing or failing. Synthetic data used for training is labelled as synthetic and never used as the reported test set.

**Consequences:** Existing unverified eval reports are archived under `docs/archive/unverified/` with a banner. CI enforces the absence of known hard-coded literals. `python scripts/dev.py acceptance --strict` honestly reports the state of each gate.
